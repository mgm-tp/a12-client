== Breaking Changes

Codemod recipes exist for some of the breaking changes. To use them, first install or update the codemod with your preferred package manager, e.g. with `pnpm`:
[source,bash]
----
pnpm install -g @com.mgmtp.a12.client/client-codemod
----

Then run the specific recipe:
[source,bash]
----
client-codemod <recipe> <path to directory with tsconfig.json>

// or as a single command
pnpx @com.mgmtp.a12.client/client-codemod <recipe> <path to directory with tsconfig.json>
----

=== Integration of Dependencies
The versions of the A12 dependencies were increased. Please check the documentation of the respective components for further migration instructions.

=== React Peer Dependency Update

The peer dependency version of `react` has been increased to `^19.2.6` to be able to use latest React features. If you are on an older React 19 version, update your `react` and `react-dom` dependencies.

Required:: Yes
Migration:: Manual, no codemod available.
Result::
+
[source,json]
----
{
  "dependencies": {
    "react": "^19.2.6",
    "react-dom": "^19.2.6"
  }
}
----

=== Stricter Typing For Sagas

The type `SagaIterator` from `redux-saga` has been replaced with `SagaGenerator` from `typed-redux-saga`.

This change improves type safety when using `yield*` with typed-redux-saga effects.
Since both types are structurally compatible at runtime, it should be transparent to consumers.

Required:: No
Migration:: Not needed
Result:: No changes required, but its recommended to update your own saga typings to also use `SagaGenerator` for better type safety.

=== Removal of Widget Customization Via widgetMap Property

Following its deprecation in A12 Client 16.1.0, the ability to customize certain A12 Widgets rendered by the A12 Client Components (like Layouts) using the `widgetMap` property is now removed.
Instead, the <</advanced/widgets, ClientWidgetMap>> can be used.

For detailed migration instructions, see the link:/docs/2025.06/ext2/CLIENT/client-documentation-bundle/index.html#_deprecation_of_widgetmap_props[deprecation,role=external] note.

The removal of the `widgetMap` property made some interfaces obsolete, which are therefore removed as well:

|===
| Interface | Replacement
| ModalRegionUiNGProps | RegionUiPropsNG
| MasterDetailLayoutPropsNG | LayoutPropsNG
| ModalRegionUiProps | RegionUiProps
| FrameViews.MasterDetailLayoutProps | FrameViews.LayoutProps
|===

Required:: Depending on whether you used the `widgetMap` property.
Migration:: Manual, no codemod available.
Result::
+
Before, when customizing the MasterDetail widget:
+
[source,typescript]
----
const customWidgetMap: FrameViews.MasterDetailLayoutProps["widgetMap"] = {
	masterDetail: CustomMasterDetail
};

export function CustomResizableMasterDetailLayout(
	props: FrameViews.MasterDetailLayoutProps
) {
	return <FrameViews.MasterDetailRegionLayout {...props} widgetMap={customWidgetMap} />;
}
----

Now, wrap the outer component with the `ClientWidgetMapContext` instead and pass your custom widget there:

[source,typescript]
----
import { useContext } from "react";
import { ClientWidgetMapContext } from "@com.mgmtp.a12.client/client-core";

export function CustomResizableMasterDetailLayout(
	props: FrameViews.MasterDetailLayoutProps
) {
	const DefaultClientWidgetMap = useContext(ClientWidgetMapContext);

	const customWidgetMap = {
		...DefaultClientWidgetMap,
		MasterDetail: CustomMasterDetail
	};

	return (
		<ClientWidgetMapContext.Provider value={customWidgetMap}>
			<FrameViews.MasterDetailRegionLayout {...props} />
		</ClientWidgetMapContext.Provider>
	);
}
----

=== Updating to ES2025

The javascript output of the npm artifacts was updated from `ES2024` to `ES2025` to be able to use latest language features. When using supported browsers, there is no change necessary. If support for older browsers is required, make sure to include necessary polyfills.

Required:: Depending on whether support for older browsers is required.
Migration:: Manual, no codemod available.
Result:: Depending on your bundler setup, consult its documentation on how to include polyfills.

=== Removal of Deep Import Paths

Deep import paths from `@com.mgmtp.a12.client/client-core` and `@com.mgmtp.a12.client/client-data` (e.g., `@com.mgmtp.a12.client/client-core/lib/core/application/index.js`) have been removed.
All exports must now be imported directly from the package root. For detailed migration instructions, see the link:/docs/2025.06/ext4/client/client-documentation-bundle#_deep_import_paths_of_a12_client_npm_packages[deprecation,role=external] note.

[NOTE]
====
The package now uses the `exports` field instead of `main`/`types`. This should be transparent for most consumers but may require configuration updates for older bundlers.
====

Required:: Yes.
Migration::
+
[source,bash]
----
client-codemod preferTopLevel <path to directory with tsconfig.json>
----
Result::
+
[source,js]
----
// before
import { ApplicationModel } from "com.mgmtp.a12.client/client-core/lib/core/application/index.js"

// after
import { ApplicationModel } from "com.mgmtp.a12.client/client-core";
----

=== Conversion of value-only namespaces into objects

Several namespaces consisting only of value exports were changed to `const` objects. This was done to improve tree-shaking support in modern bundlers.
This change should be transparent for most consumers since the usage syntax remains the same (e.g., `ActivitySelectors.activities()`).

Required:: No
Migration:: Not needed
Result:: No changes

=== Correction of Return Types

The return type of `FrameFactories.viewProvider(componentName: string)` has been corrected to `View.ViewComponent | undefined` to reflect what the method actually returns. Make sure that every time the method is used, a static default ViewComponent is chained via `??`.

Required:: Depending on whether you used `FrameFactories.viewProvider` and if you handled the case of it returning `undefined` before.
Migration:: Manual, no codemod available.
Result:: Depending on your previous usage, add a fallback for the `undefined` case.

=== Stricter ApplicationModel.isInstance type guard

The type guard for Application Models has become stricter. It now checks the model content in addition to just the model type. Any models passed to A12 Client already had to conform to this and this only affects the unlikely case you used this on models not passed to A12 Client.

Required:: No
Migration:: Not needed
Result:: No changes required

=== Redux 5 Upgrade

A12 Client has been upgraded to Redux 5 along with its ecosystem. For a complete list of breaking changes in Redux 5, refer to the https://github.com/reduxjs/redux/releases/tag/v5.0.0[official Redux 5 release notes].

Required:: Yes.
Migration:: Partial, some codemods available (see below).
Result::
+
Consists of multiple different changes, see the following sections:

==== Dependency Updates

The following peerDependency versions have been updated:

|===
| Package | Old Version | New Version
| redux | ^4.0.5 | ^5.0.0
| react-redux | ^7.2.2 | ^9.2.0
| redux-saga | ^1.1.3 | ^1.3.0
|===

Additionally, `typescript-fsa` actions have diverged from Redux actions and do not work out-of-the-box anymore. We have provided
`@com.mgmtp.a12.client/typescript-fsa-redux-5-compat` as a replacement, which is a Redux 5-compatible fork maintained by us.

==== Update Dependencies

Update your `package.json` to use the new versions:

[source,json]
----
{
  "dependencies": {
    "redux": "^5.0.0",
    "react-redux": "^9.2.0",
    "redux-saga": "^1.3.0",
  }
}
----

Remove `@types/react-redux` from your dependencies, as react-redux now ships with its own TypeScript types. Additionally, there are no peerDependency warning between React and React-Redux anymore, so you can remove any overrides or patches you had.

==== Migrate typescript-fsa Imports

Run the `migrateTypescriptFsaImports` codemod to update all imports from `typescript-fsa` to the fork:

[source,bash]
----
client-codemod migrateTypescriptFsaImports <path to directory with tsconfig.json>
----

==== Migrate AnyAction Type References

`AnyAction` from both `redux` and `typescript-fsa-redux-5-compat` are now deprecated. `AnyAction` from `typescript-fsa-redux-5-compat` is not compatible with Redux anymore, as they require action types to be strings.

`AnyAction` from `redux` is not type safe and can be migrated to the new `UnknownAction`, but its super type `Action` is often the cleaner type.

Run the `migrateAnyActionType` codemod to migrate all usages of `AnyAction` to `Action`:

[source,bash]
----
client-codemod migrateAnyActionType <path to directory with tsconfig.json>
----

==== Define Type of `State` in `useSelector`

`react-redux` now have stricter types by default. Especially the type of state in `useSelector` is now `unknown`. Selectors of A12 will not work with this type. It is recommended to define the type of the state for your application yourself, but returning to
`object` is the minimum.

You can fix this by augmenting the type of useSelector in a custom declaration file.

[source,typescript]
----
// @types/react-redux.d.ts
import type { UseSelector } from "react-redux";

declare module "react-redux" {
  export const useSelector: UseSelector<object>;
}
----

Include this in your TS compilation (e.g. with the "include" property of the tsconfig.json). Alternatively, `react-redux` provides methods to define a pre-typed version of `useSelector` and `useDispatch`.

[source,typescript]
----
import { useSelector } from "react-redux";

export const useAppSelector = useSelector.withTypes<object>();
----

You then can use this `useSelector` as a direct replacement wherever you previously imported `useSelector` from `react-redux`.

==== Potentially fix Middlewares

The typing of actions and the result of next inside middlewares have changed to be `unknown`. Most middlewares should be safe, as the first call in any middleware is usually a type guard (usually `actionCreator.match`).

If you have a generic middleware that does not care about the specific type of action and accesses `action.type` directly, you can now use the `isAction()` type guard from `redux` to ensure type safety:

[source,typescript]
----
// Before
import { type Middleware } from "redux";

const loggingMiddleware: Middleware = api => next => action => {
  console.log("Action:", action.type);
  return next(action);
};
----

[source,typescript]
----
// After
import { isAction, type Middleware } from "redux";

const loggingMiddleware: Middleware = api => next => action => {
  if (isAction(action)) {
    console.log("Action:", action.type);
  }
  return next(action);
};
----

==== Potentially fix Reducers

Same as with middlewares, the type of action in reducers is now a bit type safer and is now `UnknownAction`. Most reducers should be fine as a type guard is normally used. If not (e.g. you used action properties without type guard), you need to add one.

[source,typescript]
----
// Before
const myReducer: Reducer = (state, action) => {
	if (action.type === "CUSTOM_ACTION") {
		return action.payload.value;
	}
};
----

[source,typescript]
----
// After
import { actionCreatorFactory } from "@com.mgmtp.a12.client/typescript-fsa-redux-5-compat";

const factory = actionCreatorFactory("");
const customAction = factory<string>("CUSTOM_ACTION");

const myReducer: Reducer = (state, action) => {
	if (customAction.match(action)) {
		return action.payload.value;
	}
};
----

=== More specific typing in module-specific data reducer selectors

The typing of the `dataReducers` property in the `Module` interface and the `moduleReducers` property in the `ActivityReducers.Config` interface have been changed to be more specific.

Previously, the signature of both selectors suggested that they receive the entire state. However, since data reducers only operate on the activities slice of the state, the selectors only receive the activity map as an argument. This change allows for better type safety and clarity when implementing these selectors.

The behavior of these selectors has not changed, so if you were not using the argument before, no migration is required. If you are using the argument, make sure to update your usage accordingly.

Required:: Depending on whether you use the arguments of these selectors.
Migration:: Not needed
Result::
+
[source,typescript]
----
export interface Module {
	// ... other properties

	// Before
	readonly dataReducers?: Selector<ReadonlyArray<ActivityReducers.DataReducer>>;

	// After
	readonly dataReducers?: (activityMap: ActivityMap) => ReadonlyArray<ActivityReducers.DataReducer>;
}

export namespace ActivityReducers {
	// ... other interfaces

	export interface Config {
		// Before
		moduleReducers?(state: object): ReadonlyArray<DataReducer>;

		// After
		moduleReducers?(activityMap: ActivityMap): ReadonlyArray<DataReducer>;
	}
}
----
